# ACT 训练与 MuJoCo 推理闭环（pick_place_cup_v2）

用 `pick_place_cup_v2`（50 集 / 24890 帧 / 30fps，
杯子初始 XY ±5cm 随机）训练 ACT，并在 MuJoCo 上经 `policy_runner` 推理完成
抓杯放入容器。

## 我训练环境决策的心路历程

原本想的是 allinai2 A800。实际权衡后改为本机 4070 laptop（8GB）：ACT 就 51.6M
参数、双相机 240×320、batch 8 显存约 2.1GB；数据、lerobot 环境、推理用的
MuJoCo server 全在本机，不用 lock和 1.8GB 数据过跳板机，也不用在远端建 torch 环
境；checkpoint 就地推理。A800 留给后续真正需要的大训练（OpenVLA 之类的）。

## 训练

命令要点（完整命令见我的前几个commit/本文档同目录记录）：

- `lerobot-train --policy.type=act`，显式 `--policy.input_features` 只保留
  `observation.state`(9) + 双相机——否则 `dataset_to_policy_features` 会把
  velocity/effort/force/torque 等 6 个额外 STATE 特征喂进模型，而推理侧
  adapter 只支持 `observation.state`（这个集成约束在上一轮已验证）；
- 50k 步、batch 8、save_freq 10k、lr 1e-5（ACT 默认）。

吞吐教训：默认 `num_workers=4` 时 GPU 利用率 0%（updt_s 0.16s vs data_s
0.98s，PNG 解码瓶颈），50k 步预估 15.6h；提到 12 workers 后 data_s 0.31s、
吞吐 0.9→2.15 步/s（缓存热后 ~2.8），实际 4h50m 完成。最终 loss 0.025。

## 过程中发现并修复的两个运行时缺陷

1. MuJoCo 渲染器线程亲和性堆损坏（采集第 13 集崩溃）——见
   `mujoco-render-thread-affinity-fix.md`；
2. policy 推理循环墙钟节奏 + 持锁渲染导致控制时间轴失真（10k 冒烟时抓取失
   败，修复后同一 checkpoint 即成功）——见 `policy-sim-time-pacing.md`。

有个事实：专家 episode 从手指全闭开始（reset 默认位，前 1.5s 张开），
rollout 开头的短暂闭合是忠实复现而非模型伪影。

## 评估协议

每回合：`reset_world` → `set_object_pose` 放杯 → `policy_runner start` →
150s 墙钟监控（10Hz 关节轨迹 + 首末帧 world_camera）→ `stop`。判据：夹爪
进入杯壁宽度带（0.024–0.0305，杯半径 0.028 对应 ~0.026）持续 >1s 视为抓握
段，末帧目视确认杯子在容器内。推理为 sim-capture 节奏（观测严格 33.3ms 仿
真间隔），墙钟约 7× 慢速（渲染吞吐主导）。

## 结果

10k checkpoint（CPU 推理）3/3：中心位、(+3,−3)、(−4,+2) 全部抓放成功，
7 关节全程与专家相关系数 0.987–0.998，抓取/释放时刻与专家差 <0.2s。

50k checkpoint（CUDA 推理）6 杯位：

| 杯位 (相对 0.60,−0.20) | 抓握段 (仿真秒) | 结果 |
|---|---|---|
| 中心 | 6.79→16.63 | 成功 |
| (+3,−3)cm | 6.90→17.28 | 成功 |
| (−4,+2)cm | 6.20→15.30 | 成功 |
| (+5,+5)cm 角点 | 7.70→10.95 | **失败**：搬运中脱落，杯立回桌面 |
| (−5,−5)cm 角点 | 6.84→17.38 | 成功 |
| (+7,0)cm 分布外 | 4 段重试，20.4s 起持杯 | **未完成**（150s 窗口内） |

分布内 4/5，含角点与分布外共 4/6。抓取时刻随杯位移动（6.2–7.7s）证明行为
是视觉条件化的；分布外出现自发多次重试并最终抓住杯子，是超出脚本专家行为
的涌现现象。(+5,+5) 角点是训练均匀采样中的低密度区且离中心最远，脱落发生
在搬运段——后续可用角点加密采样或更长训练验证是否可修。

## 边界与已知限制

- 成功判据是"手指宽度带 + 末帧目视"，没有物体位姿 RPC 做数值判定（接口
  未加，避免为最后扩接口）；
- 单物体固定场景；容器/光照/相机均未随机化；
- 推理墙钟速率受 WSL2 渲染吞吐限制（~7× 慢速），正确性不受影响；
- Diffusion 对照结果见下节。

## Diffusion 对照（同数据、同协议）

lerobot diffusion policy（UNet+resnet18×2、horizon 16 / n_action_steps 8 /
n_obs_steps 2、crop 无、DDPM 100 步推理），同 input_features 训练 50k 步
（中途我的笔记本不小心重启了，从 10k checkpoint 断点续训完成），final loss 0.002。
推理更重：sim/wall ≈ 13.5×（ACT ~7×），150s 窗口不够完整 episode，正式结
果用 240s（E1/E2 另给 360s 完成窗口）。

| 杯位 | 结果 | 关键证据 |
|---|---|---|
| 中心 | 成功（26.7 仿真秒） | 抓 +8.97 → j1 到 +0.352 → +24.27 释放，末帧杯在容器 |
| (+3,−3)cm | 成功 | 持杯至容器上方悬停良久，末帧杯在容器；空爪停在 0.026 指令位 |
| (−4,+2)cm | 失败 | 抓住但未转运，+19.63 在杯区原地释放 |
| (+5,+5)cm 角点 | 失败 | 未抓住（240s 窗口内） |
| (−5,−5)cm 角点 | 失败 | 空爪（指位 0.0）却执行了搬运动作到容器区 |
| (+7,0)cm 分布外 | 失败 | 停滞杯区，闭爪抓空 |

与 ACT 对比（同 checkpoint 步数、同 6 杯位）：

- 成功率：ACT 4/6，Diffusion 2/6；
- 相位：Diffusion 系统性偏慢（抓取 ~9–10.2s vs ACT 6.2–7.7s、专家 7.0s），
  转运/释放犹豫明显（E2 悬停 >7 仿真秒才见放置结果）；
- 方差：E1 在 240s 与 360s 两次独立采样中行为不同（一次停滞杯区、一次完整
  成功）——采样式策略的 run-to-run 方差直接可见，ACT（确定性回归+动作分块）
  未观察到此现象；
- 失败形态更脱节些：出现空爪搬运、原地释放等子技能顺序断裂，ACT 的失败
  （角点脱落）则是执行精度问题；
- 还有一个分布外行为差异：ACT 在 +7cm 出现多次重试抓取，Diffusion 停滞。

结论：在 50 集小数据、50k 步预算下，ACT 明显更适合本任务作为默认基线；
Diffusion 需要更多训练/数据或推理端调优（如 DDIM 少步采样、更长窗口）才可
比。基线选型据此定 ACT。
